# 长期助手（Long Agent）前端展示

版本：1.0；2026-10-07。对应任务 `pi-003`（阶段 P1 设计收口）。
按[前端设计方法](../frontend-design-method.md)的顺序记录推导；实施与验收回写在本文件末尾。

## 1. 任务与入口

- **谁**：长期助手的拥有者（用户）。
- **对哪个对象**：一个**长期助手**（Long Agent）。
- **要完成什么**：① 想确认“它是谁、能做什么”（查看）；② 想调整某项配置（修改）；③ 想知道某项为什么是这样（追溯来源）。
- **成功**：不需要四处找入口就能看全并改对；每一项都能回答“这是什么、现在是什么值、能不能改、改了影响哪一轮”。
- **入口**：长期助手面板 → 总览（唯一可写入口）；其他入口跳转到同一处。
- **退出路径**：关闭设置回到原会话；改动在**下一轮**生效。

## 2. 当前问题与证据

| 现象 | 证据 |
|---|---|
| 界面用实现术语，用户看不懂 | `longAgentSettings.description` 标签为 **“Chat 列表摘要”**（实为“简介”）；另有“独立工作空间摘要”“当前生效装配” |
| 同一对象五种叫法 | 长期助手 / 长期智能体 / 长期同事 / Long Agent / 助手 |
| 定义 7 部分 ↔ 界面 5 标签，不对应 | 项目混在身份区；通道只读且与记忆同标签；定时任务/长期职责与“能力”平级；群组身份挂在“能力”下 |
| 入口分散 ≥4 处 | 侧栏面板齿轮 / 会话输入区「工作流智能体」/ 工作区导航两个入口 / 全局设置中心 |
| 缺功能入口 | 绑定项目无入口；通道只读、无法绑定 |

结论：定义（`pi-001`：构成 4 项 + 能力 3 类）与展示脱节，用户“既看不到也配不了”。

## 3. 信息清单（原子信息表）

见任务文档 `pi-003/02-design.md` §5（完整表）。要点：

- **集合型信息**（记忆条目、工具、技能、绑定项目、定时任务、长期职责、装配区域、用量指标）→ 必须「摘要 → 列表 → 单条」；
- **长文本信息**（身份指令、项目专属指引、规则资源正文）→ 多行编辑器 + 预览；
- **单个值**（名称、简介、模型、Thinking、默认项目、通道绑定状态）→ 行 + 控件；
- **只读观测**（本轮实际装配、用量、工作空间、通道状态）→ 折叠只读区。

## 4. 关系推导

| 关系 | 表达 | 原因 |
|---|---|---|
| 构成 vs 能力（两大类） | 左侧列表两个分组 | 定义就是这两类；性质不同不应混排 |
| 定义项 → 当前值/数量 → 入口 | 每项一行：摘要 + 基数 + 入口 | 集合型不能压成一行（记忆 128 条、工具 26 个） |
| 可写 vs 只读 | 可写项在编辑区；只读项单列“只读”分组 | 用户要能区分“我能改”和“我只能看” |
| 继承 / 覆盖 / 来源 | 字段旁标注「继承 · 可改」/「本助手覆盖」 | 与既有工作流配置范式一致，来源可追溯 |
| 对象 + 范围 + 生效时点 | 顶部固定“范围”，底部“修改 N 项 · 下次发送起生效” | 避免“改了哪里、什么时候生效”的疑问 |
| 项目级覆盖（工作流智能体） | 明确标注作用域并跳回对应行 | 与助手默认值不同层，不能混为一谈 |
