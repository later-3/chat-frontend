| 3 关系 | **回复 bar 是会话树的根入口**：每条 agent 回复一个 bar（独立、内联宽度）；展开它 = 展开这棵树：回复自己的请求直接挂在回复下（默认单节点回合不显示 workflow 中间层，它是隐形执行包装）；**显式调用的 workflow 工具是回复下的子节点**（有名字/状态、可折叠），每个 agent 节点的子会话 bar 挂在**它**下面；子会话再调 workflow 则继续嵌套，递归同理。**同级 bar 可以有（多次 workflow 调用、同一 workflow 的多个节点），但必须挂在明确父节点下**，不允许无父节点的同层 bar。人工/脚本节点不产生模型请求、无会话，是树上的叶子（显示状态，非 bar）。子会话 bar 提供“打开该会话”跳转（父子关系承载切换）。父子关系由读模型会话树投影（`session-tree-projection`）提供，渲染的是树，不新建机制。摘要条与完整历史共用同一读模型与同一 `TurnInteractions` 组件。完整记录开关开启才有原文；区域记录始终有。配置三层：本轮 > 会话 > 默认，同一数据结构、同一组件。排除不改写原记录，只影响下一轮装配。 |

## 原型 → 实现的拉齐机制（待检视确认后生效）

原型本身不自动保证与实现一致，靠四个机制咬合：

1. **同源 token**：实现必须把原型中的每个视觉决定映射到现有 CSS 变量/共享组件（映射表由开发在 B3/B4 实施时补到本记录 §实现映射），禁止第二套视觉体系（unit 禁令）；检视按映射表核对。
2. **契约门禁从验收节生成**：本记录“验收”行的每条用户行为逐条转成浏览器契约测试（断言合同不断言实现），B3/B4 交付门必跑；新增行为先改本记录再改门禁。
3. **同状态截图对照**：每批前端交付对相同状态（明/暗 × 390/1440 × 变体）提供实现截图与原型截图并排（交付文档），pi-agent 逐张对照；差异要么改实现、要么修订本记录，不允许两边各改一点。
4. **T 点用户审核**：T2/T3 在真实会话里审核效果，是最终拉齐点；你看到的应是过检视关的东西。

## 约束

- 原型与实现只用现有设计 token；不引入第二套视觉体系（unit 禁止项）。
- 展开默认收起；运行中实时更新不得导致滚动位置跳动（B4 验收项）。
- 所有数字来自读模型，前端不计算、不伪造（数据事实源合同）。
